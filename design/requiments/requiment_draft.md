
# 概要

## 目的
企業ブランドの価値向上、競合他社との競争力向上のために、開発コスト削減、開発スピード向上を行う。

## 利用者
自動車分野のECUサプライヤの従業員。
利用者には下記の種類がある。
- システムエンジニア（開発者）
- レビューアー（ドメイン有識者）
- マネージャー（製品計画策定やプロジェクト承認を行う）
- 顧客への営業窓口（製品の売り込みを行う）

利用者のITリテラシーは高くないため、GUIなどグラフィカルかつノーコードで操作できるシステムを求めている。

## 用語

| 用語 | 説明 |
|---|---|
| ECUサプライヤ | 本システムを導入する先の企業。 |
| ユーザー | ECUサプライヤの社員。利用者に該当する。 |
| 顧客 | 自動車メーカー(OEM)を指す。納品した製品を自動車に組み込む。 |
| 製品 | 顧客に納品する製品。顧客ごとに異なる名称がつく。 |
| プラットフォーム | ECUサプライヤの既存資産。過去に開発したECUのハードウェアやソフトウェアの組み合わせの総称を指す。<br>ECUサプライヤは複数のプラットフォームを持っている。 |
| A-SPICE | Automotive SPICE v4.0を指す。 |
| 開発プロセス | A-SPICEのSYS.1、SYS.2、SWE.1などの個別の活動を指す。またそれらの総称のこと。 |
| 顧客入力物 | 顧客から入力されるインプット資料。顧客ごとにドキュメント構成や形式が異なる。 | 
| 成果物 | A-SPICEに従って複数種類の成果物がある。<br>具体的には開発プロセスの中で作成するドキュメント、モデルファイル、ソースコード等を指す。 |
| リビジョン | 成果物を変更するごとに付与される。 | 
| バージョン | 顧客への製品納入などのマイルストーンに対して付与される。Gitのタグのようなもの。 | 

# ユーザー要求

## 共通要求
- AI駆動開発を適用することで、開発スピード向上やコスト削減を行う。
- 過去の資産（プラットフォーム）を活用したプロダクトライン開発を適用する。
- 開発プロセスは、A-SPICEとする。
- 製品によって採用するプラットフォームが異なるため、顧客から提供される要求仕様の形式や、開発プロセスの中で作成する成果物は異なる。
- プラットフォームや顧客ごとに異なる開発プロセスの内容（成果物の形式が異なる）が採用できること。
- ECUサプライヤの企業内のシステム間と連携しやすくするため、システムはAzure上で構築すること。

## プラットフォームと製品の扱い
- 複数の顧客の登録・変更・削除ができること。
- 顧客ごとに複数の製品の登録・変更・削除ができること。
- 複数のプラットフォームの登録、変更・削除ができること。
- 製品ごとに適用するプラットフォームおよび、ベースとするプラットフォームのバージョンが指定できること。
- あるプラットフォームから派生して別の顧客の製品で個別のカスタマイズができること。
- 個別の顧客の製品でカスタマイズした内容が、他の製品にマージできること。（将来的な要求）

## 開発プロセスの定義
- 成果物は、可能な限り生成AIを使ったワークフローで一括作成・変更すること。
- 生成AIを使って作成した成果物は決められたタイミングでユーザーが確認（承認）できること。
- ユーザーの確認タイミングはプラットフォームの想定変更量によって変わるため、ユーザーが選択可能なこと。
- 開発プロセスの定義（ワークフローやAIへの指示）は、一元管理されていること。（個人の開発PCごとに異なる状態にしないこと)
- 開発プロセスの定義は、システム導入企業が1プラットフォーム、1製品分を作成する。
- システム導入後にECUサプライヤの社員が、他のプラットフォーム・顧客・製品の開発プロセスを定義・変更できること。
- ECUサプライヤの社員が、開発プロセス（ワークフロー）の作成・変更をを生成AIでサポートで可能なこと。
- 高い製品品質が求められるため、各開発プロセスにガードレールを設けること。

## 成果物の管理
- 成果物に関する情報は、システムで一元管理されていること。（各ユーザーの個人PCで管理しない)
- 各成果物の単位でトレーサビリティを設定すること。
- 成果物の変更(リビジョン)を管理すること。
- 顧客へのリリースタイミング等、ユーザーの指示で成果物にバージョンを付与できること。
- 全ての成果物は、顧客からの仕様変更や内部的な不具合検出など何らかの入力に基づいて変更すること。
- リリースに含まれる仕様変更や不具合対応などの内容がユーザーにレポートできること。

## 製品窓口対応
- 顧客入力物の変更によって影響を受ける内容や成果物の量などの、顧客説明や計画立案に必要な資料をレポートとして出力できること。
- 顧客からの製品の説明を求められたときに必要なシステムの機能構成や概要などの資料をレポートとして出力できること。
- ユーザーがレポートする内容を変更できること。

## LLMエンジニアリング
- コスト削減のために、ワークフロー実行にかかったトークン数やコストが確認できること。
- ワークフロー上のプロンプトを定量的に評価できること。


# システム要件
## システム構成
- SYSプロセスは、開発者のブラウザから、Webアプリで成果物の生成やユーザーの修正、確認までを実施する。
- SWEプロセスは、SimulinkやCANoeなどのツールを使う必要があるため、開発者のPC上でGitHub Copilotを使用する。
- SYSプロセスとSWEプロセスの成果物のトレーサビリティを取れるようにするため、成果物はクラウド上で管理する。
- 使用するクラウドが変更になっても利用できるよう、クラウド事業者が提供するマネージドサービスは極力使用せず、OSS等を利用する。
- 開発効率やスケーラビリティ、不具合リスク、運用コスト等を比較して、クラウド事業者固有のサービスの利用したほうが有利な場合は、マネージドサービスを利用する。
- Webアプリは、Next.jsを使って構築する。
- 成果物に使用されているSysMLの図形は、ブラウザで図形編集可能とする。
- 成果物に使用されている表は、ブラウザで編集可能とする。


## ユーザ管理（将来的な要求）
- ユーザーの追加・削除が可能なこと。
- ユーザー認証したうえでシステムを利用可能とすること。
- ユーザーによって、パーミッションを設定できること。
- パーミッションは、顧客単位、顧客の製品単位、プラットフォーム単位、開発プロセス単位に、書込可能(作成・変更・削除)と閲覧のみを指定可能とする。

## 顧客・製品管理
- 顧客情報の登録・変更・削除・一覧表示、検索（フィルタ）ができること。
- ユーザーのパーミッションは個別の顧客単位に設定できること。
- 顧客ごとに製品情報の登録・変更・削除・一覧表示、検索（フィルタ）ができること。
- 製品登録時に、ベースとして採用するプラットフォームのバージョンを必ず指定すること。
- 採用するプラットフォームは変更不可とする。

## プラットフォーム管理
- プラットフォーム情報の登録・変更・削除・一覧表示、検索（フィルタ）ができること。

# 成果物の構成管理
- ある時点の成果物から、過去の変更履歴（リビジョン）が全てたどれること。
- 製品のベースとしたプラットフォームのバージョンよりも過去のリビジョンも参照可能とすること。<br>（AIが変更理由をたどれるようにするため）
- 顧客の製品単位にバージョンを付与できること。
- 顧客・製品・プラットフォーム・成果物のデータは、独自に構築したMCPサーバー内で内部管理する形式への変換、リビジョン・バージョン管理、トレーサビリティ担保、検証を行った上でデータベースへ登録、取得を行う。（エージェントはDBの構成を意識せずMCPのインタフェースのみを意識する）
- MCPサーバーが扱う、顧客・製品・プラットフォーム・成果物のデータは、Azure上のPostgreSQLで管理する。
- MCPサーバーでRAG検索を行うためにPostgreSQLのpgvectorを使用する。
- 顧客入力物の生データは、Azure Blob Storageで管理する。
- 顧客入力物の生データの削除タイミング（世代数や期間など）はECUサプライヤや設定可能とする。

# 開発プロセス管理
- 開発プロセスのワークフローで使用するプロンプトはユーザーが変更可能なこと。
- 利用するLLMのモデルは、Microsoft Foundryから選択して使用する。
- 生成AIのワークフローはn8nを使用する。商用利用可能なOSSであり、生成AIによるワークフロー作成が搭載されているため。
- Webアプリからワークフローの起動は、n8nのWebhookのGET/PUTをトリガーとする。
- プロンプトは、バージョン管理が行えること。
- プロンプトのバージョン管理は、Langfuseと、n8nのfangluseノード(n8n-nodes-langfuse)を使用して実現する。
- ユーザーが変更したプロンプトは、試行（テスト）したうえで本番環境に適用できること。
